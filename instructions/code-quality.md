# 实现质量与缺陷治理通用细则

## 范围与权限

- 非平凡功能、缺陷修复，以及生产代码、工具或脚本的新增、修改、重构和审查必须读取本文件；纯文档、纯美术或不改变行为的序列化数值调整不必读取。
- 用户当前要求与消费项目根 `AGENTS.md` 决定产品范围、验证、提交、发布和破坏性操作权限；本文件只规定工程质量，不以“改动必须最少”为目标，也不自行增减权限。
- 项目细则可以补充领域事实，但不得保留重复权威、错误职责、新旧双轨或 fallback。规则冲突无法同时满足时，在写入前列出冲突与影响并请求用户决定。

## 权威、职责与数据流

- 修改前明确入口、唯一 owner、producer、不可变产品或状态、publication/adoption、生命周期、consumer、错误边界和验证路径；关系未查清时不得直接加字段、分支、guard 或补偿。
- 同一事实只有一个权威来源。consumer 不得推导、修正或覆盖 producer 应提供的状态；缓存必须声明 owner、失效、刷新和生命周期。
- 配置归行为 owner 所有。实例、宿主、模板、皮肤或 Variant 可变的 Prefab/Scene/UXML/USS/Asset/Inspector 接线标识由实际 consumer 或其专用配置序列化持有；只有类型内部创建并消费、对所有实例不变或由框架契约固定的标识才可写成常量。迁移后删除旧常量和字面量。
- 资格、权限、存在性和策略直接消费对应 owner 的契约，不得用 tag、命名、目录、层级、UI 状态或偶然副作用代理。`IGameItem` 的存续只看 `IsDestroyed`；`IsInGame`、Owner、容器和阵营是独立资格，按实际产品契约分别读取。
- 类型、组件和方法保持单一功能职责与一致抽象层级；独立状态、权限、生命周期、策略或失败模式应形成职责命名的协作者。依赖通过引用、参数、接口或权威数据产品表达，禁止隐藏查找、无 owner singleton、静态可变状态和调用顺序耦合。

## 正常路径、契约与状态

- 新功能和内容优先进入现有权威 producer/product/consumer 链。只有真实存在不同领域语义、owner、生命周期、状态、权限、数据形态、交互/渲染或失败契约时才建立分支；差异结束后重新汇入公共处理。
- 已审计链中没有运行时、Editor、authoring、序列化、继承、测试、公开扩展或独立职责 consumer 的组件及其专用字段、引用、节点、资源和测试应删除；假想的未来复用不构成职责。
- 生产实现禁止用 fail-close、防御 guard、静默 return/disable、吞异常、默认替代、clamp、重试、旧缓存、备用 route、降级模式、兼容 wrapper 或第二路径掩盖契约违例。真实产品选择由 owner 建模为互斥契约。
- producer、caller 或配置 owner 一次保证前置条件和生命周期顺序；违例在首个可归因边界携带 owner、输入和阶段直接暴露。发现 guard/fallback 时修正上游并删除分支及其字段、序列化数据和测试。
- 可推导、重复、只记录 ready/fail/fallback、只服务 guard/重试/恢复或跨层手工同步的状态应删除。保留状态必须对应不可推导事实，并能指出唯一 writer、创建事件、consumer 和退出迁移。
- 创建/销毁、订阅/退订、注册/注销、租用/归还和异步启动/取消由明确 owner 成对闭合；不得用延迟、重复调用、刷新多次、隐藏反馈或参数调节掩盖所有权和时序错误。

## C# 类型与文件

- 每个手写 `.cs` 文件只声明一个顶层类型；独立类型进入同名职责文件。嵌套类型必须真正从属于外层实现，没有独立 owner、生命周期或外部 consumer。
- 手写 `class`/`record class` 的完整声明跨度不超过 1500 个物理行，attribute、注释、预处理和嵌套类型计入；职责已经分裂时应更早提取，禁止用压行、region 或嵌套容器规避。
- 手写生产代码、工具和测试禁止新增 `partial`，也不得向既有手写 `partial` 增加职责。修改既有 `partial` 时按聚合类型审查并提取真实协作者，删除旧状态与路径；仅编译器、生成器或框架硬契约可例外，且不得手改生成文件。
- 修改含多顶层类型、超限 class 或违规 `partial` 的既有类型时，先修复其结构再扩展行为。项目可以收紧，但不得放宽这些门禁。

## 观测、数学与性能

- 观测是缺陷链的一部分。异常、Console、trace、Gizmo、报告或工具不足以复现输入、关联阶段或定位首个错误边界时，先修权威观测 producer；不得以 TODO、猜测或散落临时日志继续归因。
- 面向人的摘要可舍入，但必须携带稳定 evidence ID。结构化证据保留 round-trip 数值、单位、坐标系、owner、revision/context、阶段输入输出和首个 rejection；Exception、报告、工具与可视化消费同一不可变产品。
- 连续几何、概率、搜索或优化先定义变量、单位、坐标系、方程/不等式、事件边界、定义域与可行域，再声明目标、tie-break、完备性、精度和最坏时间/空间/分配/主线程预算；固定步长、加密采样和随机试探不能代替连续域证明。
- 含多个数据相关循环/递归轴、穷尽或图搜索、事件/几何枚举、全量 Asset 扫描、逐项昂贵调用或笛卡尔积的实现、测试、Gizmo 和 Editor tool，在首次可执行写入前提交 `Static Cost Ledger`：列出各轴来源及冻结输入上界、真实乘积、最坏迭代和昂贵调用总数、分配峰值、线程/同步点、缓存 owner/失效条件、预算及 `pass/fail`。
- 账本有未知项或超预算即为 `fail`，先改变算法或职责。循环、嵌套、输入域、线程、缓存或 owner 调用变化会使账本失效；编译、平均耗时、提前退出、异步化和单次 Profiler 结果不能替代静态上界。

## 复用、迁移与兼容

- 实现前搜索已有组件、接口、产品、触发器、Prefab/Scene 接线、配置、测试和文档；能表达需求时组合或泛化现有职责，禁止复制状态、生命周期、订阅和业务规则。抽象必须有真实独立职责、稳定契约、变化轴或 consumer。
- 契约变化同步更新全部受控 producer、consumer、测试、序列化接线和有效文档；迁移后删除旧 API、route、schema、字段、事件、配置、适配器、别名和一次性代码，不保留新旧双轨。
- 兼容性默认关闭。除非用户明确点名对象与边界，只实现当前权威契约；唯一常设例外是用户维护的跨项目通用 package/plugin/Editor extension 对其声明支持的 Unity 版本进行编译期兼容，具体执行 package 细则。
- 命名表达领域职责、方向、单位和失败语义；泛化名称不得掩盖多项职责。注释只记录代码无法表达的原因与硬约束。新增或修改的源码和脚本只保留一个 EOF 换行。

## 因果测试与缺陷族

- 测试、演示和自动化从生产入口、触发条件、状态 owner、效果 consumer 与玩家可见结果反推“刺激 -> 权威触发/属性 -> 效果 -> 观察”，并提供除被测机制外匹配的对照。
- 持续、周期、tick、cooldown 或可重复效果必须跨有意义时间窗持续提供真实刺激并留下多次结果；测试基础设施按实际 Prefab、Property 和 timer 契约推导脉冲数、时长与 owner/control 对称性，不使用对象 ID 白名单。
- 场景只保留因果和生命周期需要的参与者。可直接注入权威事件时不得生成会移动、攻击、结束战斗或制造第二刺激的默认单位；硬契约锚点必须显式命名职责并隔离无关行为。
- 范围内由错误日志、最小复现、公开契约矛盾或权威状态确认的 Bug 优先于依赖它的后续工作。冻结当前实现和测试语义，审计同一 owner、机制和数据流的入口、状态组合、Variant、guard/fallback、consumer 与相邻失败模式后统一修复。
- 已有具体输入、暂停帧、不可变产品或事务时，先让 exact witness 沿真实生产链确定性回放，记录各阶段 owner、revision/context、输入输出和首个非法迁移；随后补齐独立场景、完整状态矩阵、传播链和竞争解释。单个 witness 只定位失败边界，不能直接命名系统根因。
- 根因结论必须说明可构造前置、唯一 owner、错误迁移、全部相关入口与状态组合的传播链、修正后应消失的反例及已排除解释。缺项时只记为待验证假设。
- Comparator、排序、tie-break、阈值、budget、candidate 数、cadence、延迟或新增 flag/mode/cache/pending/type，只有在其本身是已证明的产品事实且能从 producer 消除非法迁移时才是修复；运行更久、失败后移或异常换位置不是修复。有限搜索中排序只拥有性能与确定性，不拥有正确性。
- 原子工作改为跨 tick、异步、分帧、增量或可恢复事务会新增生命周期与 publication 时序，必须重新证明状态可达、唯一 writer、退出/取消和活性。新证据否决的实验必须先撤回，不能与下一假设叠加。
- 单场景在首个非法状态结束；同一冻结 build 上其他独立且属于本轮范围的场景继续完成。一次 coherent 修复应消除同源非法迁移并删除失去用途的 guard、fallback、状态和测试；编译通过、截图或单次成功不能替代结构正确性。

## 交付前自审

- 代码或编译契约变化执行 `unity-editor-safety.md` 的权威编译门禁；失败时收集错误族、修正并重新编译到 error 为零。编译只证明编译契约。
- 重新核对 `Static Cost Ledger` 与当前实现一致，并审查完整 diff 及生产链的权威、职责、状态 writer、控制流、生命周期、错误、API/序列化面、命名、死代码、临时诊断和相邻回归。
- 确认不存在 fallback、防御 guard、内容特判、手工同步、隐藏顺序、任意延迟、重试、吞错、旧实现或仅移动失败位置的参数/排序改动；受用户明确限制或环境阻碍而未执行的验证准确标为未验证，并说明原因。
